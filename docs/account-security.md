# 第二批本地安全加固

本功能先完成本地和独立数据库验收，后随 2026-11-11 版本部署到公网。线上邮件功能继续关闭，没有向外部地址发送测试邮件；部署记录见 [deployment-status.md](deployment-status.md)。

## 当前启用范围

2026-11-10：目前以本人使用为主，邮件找回密码、邮箱验证与线上发信接入暂缓，待购买域名后再接续。
保留已实现的代码和本地 SMTP 验收脚本；默认 `MAIL_ENABLED=false`、`REQUIRE_VERIFIED_EMAIL_FOR_PUBLICATION=false`。
关闭邮件时，登录页隐藏找回入口，账号安全页隐藏邮箱验证；直接访问相关页面会提示未启用。
申请、确认及重置接口均拒绝邮件操作（503），已签发且尚未过期的邮件链接也不能在关闭期间消费。
登录、私人写作、广场发布与公开正文编辑、修改密码、退出所有设备及账号配额继续可用。
修改密码仍要求当前密码；当前没有可用的邮件恢复渠道，请妥善保存密码。
以后启用发信并完成投递验收后，再按公开站点需求显式开启发布验证门槛。

## 行为

- `/account/security` 展示邮箱归属状态、有效会话数、实际文本字节用量及条目配额。
- 改密码、退出全部设备、申请绑定/更换邮箱均要求再次输入当前密码。错误返回 403；同一账号每分钟最多 5 次再次验证，来源也有限额。
- 修改密码或密码恢复会撤销全部会话与全部未使用邮件凭证。退出全部设备也撤销会话及未使用邮件凭证。
- 登录使用账号行锁读取最新密码哈希并签发会话，避免旧密码校验与改密竞态。排队写入取得账号锁后重新检查会话撤销。
- 邮箱验证链接 30 分钟有效，密码重置链接 15 分钟有效。256 位安全随机数、SHA-256 存储、用途隔离、单次消费；重新申请同用途链接使旧链接失效。
- 旧 user.email 继续作为未验证资料保留，不会自动用于恢复。邮箱验证表中的地址唯一，按去首尾空白、小写形式归一化；不会采用服务商特有的去点号等规则。
- 更换邮箱需要当前密码与新邮箱链接确认；确认之前旧归属继续有效，确认后撤销全部会话和旧链接，并向原已验证邮箱发送安全提醒。
- 找回密码只使用已验证邮箱；存在与不存在的邮箱响应相同，发信异步执行。凭证不返回 API、不输出日志，不会自动登录。
- URL 只从 MAIL_PUBLIC_BASE_URL 生成，不信任 Host/转发头。一次性凭证放在 URL 片段，打开页面后移除片段，由用户确认后 POST 消费，避免普通邮件预览触发操作。
- 修改密码、重置密码会向已验证邮箱发送安全提醒。恢复页面只清理目标账号在当前浏览器中的凭证，避免误清理另一个账号。

## 配额与注册滥用

默认每账号 20 MiB（20971520 字节）、1000 篇日记、10000 条补记、200 个分类。
统计标题、正文、补记、分类名及描述的实际 UTF-8 字节；不统计数据库索引和行元数据。
按实际数据计算，不依赖可漂移的前端或缓存计数。所有内容变更先锁同一账号再检查和提交，防止并发突破上限。
超额返回 409 并回滚；删除释放空间；已超额的历史数据仍可缩短或删除。

保留第一批注册限频/关闭注册配置，并对邮件申请按来源、账号或邮箱哈希限流，默认邮箱每小时 3 次。
显式开启 `REQUIRE_VERIFIED_EMAIL_FOR_PUBLICATION=true` 后，广场发布以及修改已公开正文要求验证邮箱；私人写作不受影响。旧已公开文章不会自动撤回，但修改公开正文前需验证。
邮箱验证只能提高批量注册成本，不能替代边缘防护、异常检测或 CAPTCHA。

## 邮件配置

邮件默认关闭。未启用时申请、确认及重置链接均返回 503，不降级为控制台凭证或模拟发送。接口只公开 mailEnabled。

环境变量均见 `.env.example`：

| 变量 | 用途 |
| --- | --- |
| MAIL_ENABLED | 显式启用真实 SMTP 发信 |
| MAIL_HOST / MAIL_PORT | SMTP 地址和端口 |
| MAIL_USERNAME / MAIL_PASSWORD | 发信凭证，保存在环境变量中 |
| MAIL_FROM | 服务商授权的发件地址 |
| MAIL_PUBLIC_BASE_URL | 真实 HTTPS 站点根地址；仅本机允许 HTTP |
| MAIL_STARTTLS_REQUIRED | 默认 true，要求升级 TLS |
| MAIL_SSL_ENABLED | 隐式 TLS 服务可设 true，并按服务商要求关闭 STARTTLS |
| SENSITIVE_PER_MINUTE / EMAIL_PER_HOUR | 敏感操作及邮件申请额度 |
| MAX_STORAGE_BYTES / MAX_ARTICLES / MAX_COMMENTS / MAX_CATEGORIES | 配额 |
| REQUIRE_VERIFIED_EMAIL_FOR_PUBLICATION | 默认 false；待邮件启用后，可显式设 true 要求广场发布前验证邮箱 |

非本机 SMTP 必须要求 STARTTLS 或 SSL，启用证书主机名校验。连接/读写超时各 5 秒。
单个后台线程、最多 50 条排队任务；队列满时返回 503。邮件发送失败只记录脱敏事件，不记录正文、凭证或地址。
该队列暂不持久化，服务中断或投递失败后可重新申请。生产启用前仍需核查发信域名、SPF/DKIM/DMARC、投递与退信。

## 本地验收

2026-11-10：本次暂缓邮件后的 79 项后端测试通过；前端生产构建通过。默认关闭邮件的 13 项浏览器/HTTP 验收通过，包含隐藏入口、直接访问提示、无邮箱发布及撤回、会话撤销和重启持久性；显式启用邮件的 11 项回归也通过，邮件仅由本机临时 SMTP 收取。桌面、320/390 像素窄屏与深色布局均检查。

后端运行 `mvn verify`；涵盖改密/登录竞态、会话撤销、凭证用途/过期/重放、并发消费、旧邮箱不能恢复、邮件限流、配额并发与迁移。
前端运行 `npm run build`，将 dist 内容复制到 target/classes/static 后重新 Maven 打包，使本地 Jar 包含最新前端。

`scripts/verify-account-security.py` 启动仅监听 127.0.0.1:18082 的打包服务、独立文件 H2 和临时端口 SMTP。邮件只保存在测试进程内存。
临时 H2 设置 WRITE_DELAY=0，在 Windows 结束 JVM 之前同步落盘，避免将测试库延迟写入误判成服务端会话持久性问题。
通过真实页面操作完成验证邮箱、改密码、邮件找回密码、退出所有设备，并检查重启持久性、手机/桌面/深色布局。
证据输出到 `target/account-security-browser/`，不会输出原始邮件凭证。第一批浏览器脚本仍可单独运行。

本地通过不等于全站安全审计完成；第一批记录中的可信代理配置、云端最小权限、共享限流、完整依赖与镜像扫描、备份恢复和告警仍待后续处理。
